# 01. 要件定義書 (PRD: Product Requirements Document)

## 目的
本ドキュメントは、プロジェクトの最終成果物である「肉じゃが」の仕様と、何をもってビルド成功（完成）とするかのコア要件、および回避すべきエラー状態（アンチパターン）を定義します。

## 1.1 成功判定条件 (Definition of Done / Assertions)
以下のすべての物理的・化学的状態（アサーション）を満たした段階で、本プロダクトは完成（デプロイ可能）とみなされます。

1. **化学的要件（浸透圧平衡と芳香成分）:**
   - **味の均一化:** スクロース（糖分）とアミノ酸（醤油）の分子が細胞内外の浸透圧勾配に従い移動し、中心部まで平衡状態に達していること。
   - **メイラード反応の完了:** 初期加熱によって生成されたメラノイジン（褐色色素および香気成分）が溶媒全体に拡散し、特有の芳香プロファイルが形成されていること。
2. **物理的要件（熱変性と糊化）:**
   - **主炭水化物（じゃがいも）:** 細胞内のデンプン粒が水分を吸収して膨潤し、完全にα化（糊化）している状態。
   - **主タンパク質（肉類）:** タンパク質の熱凝固（変性）が完了しつつも、スクロースの保水効果により過度な水分の脱離（パサつき）が防がれている状態。
3. **UI/UX要件（テクスチャの共存）:**
   - じゃがいもの表面のエッジ（角）は明確に維持され視覚的インテグリティを保っている一方で、プローブ（箸や歯）のわずかな応力によって崩壊する「ホロホロ感」が物理的に共存していること。

## 1.2 除外条件およびアンチパターン (Must-Not-Have / Errors)
以下の状態が一つでも発生した場合、深刻なバグまたは別プロジェクトへのフォークとみなし、ビルドはフェイル（失敗）と判定されます。

1. **カレープロジェクトへの強制フォーク (Unauthorized Fork):**
   - クミン、ターメリック、コリアンダー等の強力な揮発性テルペン類（スパイス群）が混入した場合、出力結果は不可逆的に「カレー」という別プロダクトへフォークします。本プロジェクト内でのこれらのライブラリの依存関係は厳禁（Deprecated）とします。
2. **シチュー化（非ニュートン流体エラー）:**
   - じゃがいもの過剰な煮崩れによりデンプンが溶媒（汁）へ大量流出し、溶媒が粘性を持つ非ニュートン流体へと変化した状態。
   - この状態に陥ると、鍋内部の熱対流が停止し、底部での局所的な異常加熱（焦げ付きバグ）を引き起こすため、クリティカルなシステムダウンとみなします。
3. **ドライアウト（完全な溶媒喪失）:**
   - 溶媒（水）が完全に蒸発し、食材が直接鍋肌で炭化（焦げ）し始めた状態。本プロジェクトのデフォルト設定は「少量の高濃度調味液が底部に残るバランス型」です。

## 1.3 サポート環境 (ローカライゼーション仕様)
地域によるプロトコルの違いは、環境変数またはブランチとして並行稼働をサポートします。
- `REGION=Kanto` (関東仕様): 豚肉（単胃動物）を使用。融点が低く、まろやかな脂質プロファイルを持つ。
- `REGION=Kansai` (関西仕様): 牛肉（反芻動物）を使用。旨味が強く、ルーメン発酵由来の特有の脂肪酸組成を持つ。

## 1.4 Known Issues / 課題表 (Warning)

最終的なユーザー体験（UX）において、システム側では完全にコントロールできない変数について記述します。

> [!WARNING]
> **Issue 1: ユーザー（実食者）のセンサー個体差**
> - **現状:** ユーザーごとの唾液分泌量（アミラーゼ活性）、舌の味蕾密度、および過去の食経験（主観的データベース）により、同じ浸透圧・塩分濃度のプロダクトであっても「美味しい」「しょっぱい」「甘すぎる」といったUXのブレが生じる。
> - **結論:** これはユーザー側のハードウェア/ソフトウェア依存の問題であるため、本システムでは「平均的な人間が美味と感じる浸透圧（塩分濃度約1.0%前後）」をターゲットとし、個別のカスタマイズ（追い醤油パッチなど）はエンドユーザーの裁量に委ねる。
